# คู่มือเชื่อมโปรเจกต์กับ GitHub และเปิดเว็บด้วย GitHub Pages

มีสองทางเลือก เลือกทางเดียวก็พอ

- **ทางที่ 1 — GitHub Desktop** กดปุ่มทั้งหมด ไม่ต้องพิมพ์คำสั่ง **แนะนำทางนี้**
- **ทางที่ 2 — Command line** เร็วกว่าถ้าคุ้นกับเทอร์มินัลอยู่แล้ว

---

## ขั้นที่ 0 — เตรียมก่อนเริ่ม (ทำครั้งเดียว)

### 0.1 สมัครบัญชี GitHub

ที่ https://github.com/signup ใช้อีเมลบริษัทหรืออีเมลส่วนตัวก็ได้
ถ้าจะให้คนอื่นในองค์กรร่วมแก้ไขในอนาคต แนะนำสมัครด้วยอีเมลบริษัท

### 0.2 ตัดสินใจว่า repo จะเป็น public หรือ private

| | Public | Private |
|---|---|---|
| GitHub Pages | ใช้ได้ฟรี | ต้องใช้แพ็กเกจเสียเงิน |
| ใครเห็นโค้ดได้ | ทุกคนบนอินเทอร์เน็ต | เฉพาะคนที่เชิญ |

ข้อมูลจริงอยู่ใน SharePoint และต้องล็อกอินก่อนเข้าถึงเสมอ
แต่โค้ดหน้าเว็บและไฟล์ใน `data/mock` จะเปิดให้อ่านได้ถ้าเลือก public

**ถ้าองค์กรรับ public ไม่ได้** ทางเลือกคือ Azure Static Web Apps ซึ่งมีแพ็กเกจฟรี
ตั้งเป็นส่วนตัวได้ และต่อโดเมนเองได้ วิธีพัฒนาไม่ต่างจาก GitHub

### 0.3 ล้างข้อมูลตัวอย่างก่อน push (สำคัญถ้าเลือก public)

ไฟล์ `data/mock/directory.json` มีชื่อและอีเมลที่ผมสร้างเป็นตัวอย่างไว้
ตรวจให้แน่ใจว่าไม่มีชื่อ อีเมล หรือเบอร์ต่อของคนจริงอยู่ในนั้นก่อนอัปโหลด

ข้อมูลจริงจะไปอยู่ใน SharePoint ทั้งหมด ไม่ต้องเก็บไว้ในโค้ด

## ทางที่ 1 — GitHub Desktop (แนะนำ)

### 1.1 ติดตั้ง

ดาวน์โหลดที่ https://desktop.github.com ติดตั้งแล้วเปิดโปรแกรม
กด **Sign in to GitHub.com** แล้วล็อกอินด้วยบัญชีที่สมัครไว้

เมื่อถามชื่อและอีเมลสำหรับบันทึกประวัติการแก้ไข ให้ใส่ชื่อจริงกับอีเมลบริษัท
ค่านี้จะติดไปกับทุกครั้งที่บันทึก ใช้ดูย้อนหลังว่าใครแก้อะไร

### 1.2 สร้างที่เก็บโค้ด

1. เมนู **File → Add Local Repository**
2. กด **Choose…** แล้วเลือกโฟลเดอร์ `ppg` ที่แตกไฟล์ไว้
3. จะขึ้นข้อความว่าโฟลเดอร์นี้ยังไม่ใช่ repo พร้อมลิงก์ **create a repository** ให้กดลิงก์นั้น
4. กรอกข้อมูล

| ช่อง | ค่าที่ใส่ |
|---|---|
| Name | `prime-power-intranet` |
| Description | ระบบภายในองค์กร Prime Power Group |
| Git ignore | None (มีไฟล์ `.gitignore` อยู่แล้ว) |
| License | None |

5. กด **Create repository**

### 1.3 บันทึกครั้งแรก

หน้าจอซ้ายจะแสดงรายการไฟล์ทั้งหมดที่กำลังจะบันทึก

1. ช่อง **Summary** ด้านล่างซ้าย พิมพ์ `โครงเริ่มต้น: 8 หน้า พร้อมข้อมูลตัวอย่าง`
2. กด **Commit to main**

ตอนนี้บันทึกอยู่ในเครื่องแล้ว แต่ยังไม่ขึ้น GitHub

### 1.4 อัปโหลดขึ้น GitHub

1. กด **Publish repository** ที่แถบด้านบน
2. ชื่อ repo ปล่อยตามเดิม
3. **สำคัญ** ถ้าต้องการให้ GitHub Pages ใช้ฟรี ต้อง **เอาเครื่องหมายถูกออกจาก Keep this code private**
4. กด **Publish repository**

รอสักครู่ ไฟล์จะขึ้นไปอยู่บน GitHub เรียบร้อย

## ทางที่ 2 — Command line

### 2.1 ตรวจว่ามี Git แล้วหรือยัง

เปิด Terminal หรือ Command Prompt แล้วพิมพ์

```bash
git --version
```

ถ้าขึ้นเลขเวอร์ชันแปลว่ามีแล้ว ถ้าไม่ขึ้นให้ติดตั้งจาก https://git-scm.com/downloads

### 2.2 ตั้งชื่อผู้แก้ไข (ทำครั้งเดียวต่อเครื่อง)

```bash
git config --global user.name "ชื่อของคุณ"
git config --global user.email "อีเมลบริษัท"
```

### 2.3 สร้าง repo เปล่าบน GitHub

ไปที่ https://github.com/new

| ช่อง | ค่าที่ใส่ |
|---|---|
| Repository name | `prime-power-intranet` |
| Public / Private | Public (ถ้าจะใช้ Pages ฟรี) |
| Add a README file | **ไม่ต้องติ๊ก** |
| Add .gitignore | **None** |

กด **Create repository** แล้วคัดลอก URL ที่ขึ้นมา

### 2.4 อัปโหลดโค้ด

เปิดเทอร์มินัลในโฟลเดอร์ `ppg` แล้วรันทีละบรรทัด

```bash
git init
git add .
git commit -m "โครงเริ่มต้น: 8 หน้า พร้อมข้อมูลตัวอย่าง"
git branch -M main
git remote add origin https://github.com/<ชื่อบัญชี>/prime-power-intranet.git
git push -u origin main
```

**ตอน push จะถามรหัสผ่าน — อย่าใส่รหัสผ่านบัญชี GitHub** เพราะเลิกรองรับไปแล้ว
ต้องสร้าง Personal Access Token แทน

1. ไปที่ https://github.com/settings/tokens → **Generate new token (classic)**
2. Note ใส่ `intranet-dev`, Expiration เลือก 90 days
3. ติ๊กเฉพาะ **repo**
4. กด Generate แล้ว **คัดลอกเก็บไว้ทันที** เพราะจะไม่แสดงอีก
5. เอา token นี้ไปวางแทนรหัสผ่านตอนที่ระบบถาม

## ขั้นที่ 3 — เปิด GitHub Pages

ทำเหมือนกันทั้งสองทาง

1. เข้าหน้า repo บน github.com
2. แท็บ **Settings** ด้านบน
3. เมนูซ้าย **Pages**
4. ที่หัวข้อ Build and deployment

| ช่อง | ค่าที่เลือก |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` |
| Folder | `/ (root)` |

5. กด **Save**

รอประมาณ 1–3 นาที รีเฟรชหน้า จะขึ้นแถบสีเขียวพร้อม URL

```
https://<ชื่อบัญชี>.github.io/prime-power-intranet/
```

**URL นี้คือค่าที่ต้องเอาไปใส่เป็น Redirect URI ตอนจดทะเบียนแอปใน Entra ID**

## ขั้นที่ 4 — ตรวจว่าใช้งานได้จริง

เปิด URL แล้วไล่เช็ก

- [ ] โลโก้ขึ้นบนแถบเมนู
- [ ] เมนู 10 รายการขึ้นครบ
- [ ] กดเมนูบุคลากรแล้วเห็นการ์ดแยกตามฝ่าย
- [ ] กดเมนูแบบฟอร์มแล้วเห็นการ์ด 19 ฟอร์ม
- [ ] กด F5 ตอนอยู่หน้าอื่นแล้วยังอยู่หน้าเดิม ไม่เด้ง 404

ข้อสุดท้ายสำคัญ เป็นตัวยืนยันว่า hash routing ทำงานถูก

**ถ้าหน้าขาวเปล่า** กด F12 เปิด Console ดูข้อความสีแดง
สาเหตุที่พบบ่อยที่สุดคือ path ขึ้นต้นด้วย `/` ซึ่งใช้ไม่ได้เพราะเว็บอยู่ใต้โฟลเดอร์ย่อย
ทุก path ในโปรเจกต์นี้เป็นแบบสัมพัทธ์อยู่แล้ว อย่าแก้ให้ขึ้นต้นด้วย `/`

## ขั้นที่ 5 — วิธีทำงานประจำวันหลังจากนี้

### ด้วย GitHub Desktop

1. แก้ไฟล์ในโปรแกรมแก้โค้ดตามปกติ
2. เปิด GitHub Desktop จะเห็นรายการไฟล์ที่เปลี่ยน พร้อมไฮไลต์บรรทัดที่แก้
3. พิมพ์ Summary สั้น ๆ ว่าแก้อะไร เช่น `ย้ายหน้าติดตามสถานะ`
4. กด **Commit to main**
5. กด **Push origin**

เว็บจะอัปเดตเองภายใน 1–2 นาที ไม่ต้องอัปโหลดไฟล์เอง

### ด้วย Command line

```bash
git add .
git commit -m "ย้ายหน้าติดตามสถานะ"
git push
```

### ข้อแนะนำเรื่องการบันทึก

บันทึกบ่อย ๆ ทีละเรื่อง ดีกว่าบันทึกครั้งเดียวตอนแก้ไปสิบเรื่องแล้ว
เพราะเวลาเว็บพัง จะย้อนกลับไปทีละก้าวได้ และรู้ว่าพังเพราะการแก้ครั้งไหน

เขียน Summary เป็นภาษาไทยได้ ไม่มีปัญหา

## ปัญหาที่พบบ่อย

**เปิด URL แล้วขึ้น 404 ทั้งที่เพิ่งกด Save**
Pages ใช้เวลา deploy 1–3 นาที รอแล้วรีเฟรชใหม่
ถ้าเกิน 5 นาทีให้ดูแท็บ **Actions** ในหน้า repo ว่ามีขั้นตอนไหนขึ้นสีแดง

**เว็บไม่อัปเดตทั้งที่ push แล้ว**
เบราว์เซอร์จำไฟล์เดิมไว้ กด Ctrl+Shift+R หรือ Cmd+Shift+R เพื่อล้างแคช

**push ไม่ได้ ขึ้นว่า authentication failed**
ใส่รหัสผ่านบัญชีแทน token ให้กลับไปทำขั้นที่ 2.4 เรื่อง Personal Access Token
หรือเปลี่ยนไปใช้ GitHub Desktop ซึ่งจัดการเรื่องนี้ให้เอง

**เผลอ push ข้อมูลจริงขึ้น public ไปแล้ว**
การลบไฟล์แล้ว commit ใหม่ไม่พอ เพราะประวัติเก่ายังเก็บไฟล์นั้นอยู่และเปิดดูได้
วิธีที่ปลอดภัยที่สุดคือลบ repo ทิ้งแล้วสร้างใหม่ ทำทันทีที่รู้ตัว

## ขั้นต่อไปหลัง Pages ขึ้นแล้ว

1. คัดลอก URL ของ Pages ไปใส่เป็น Redirect URI ตอนจดทะเบียนแอปใน Entra ID
2. ระหว่างรอสิทธิ์จากไอที ย้ายหน้าที่เหลือได้ตามปกติ
3. เมื่อได้ Client ID และ Tenant ID แล้ว ใส่ใน `scripts/core/config.js`
   แล้วเปลี่ยน `dataSource` จาก `'mock'` เป็น `'sharepoint'`
